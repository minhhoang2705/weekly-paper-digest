Key idea

cyber-xiaoya-live là một hệ thống mã nguồn mở điều khiển livestream bằng người ảo (digital human) tương tác theo thời gian thực kết nối với nền tảng Vidu s2. Dự án tích hợp pipeline hoàn chỉnh gồm nhận đạn mạc (bình luận trực tiếp), xử lý LLM, tổng hợp giọng nói (TTS OmniVoice trên máy cục bộ) và đẩy lệnh điều khiển khẩu hình, hành động lên Vidu qua WebRTC.

Problem

Chi phí thuê trọn gói dịch vụ AI livestream trên đám mây (gồm ASR, LLM, TTS, avatar rendering) thường rất tốn kém và bị phụ thuộc nhà cung cấp, thiếu sự kiểm soát về tính cách, âm sắc và kho động tác tương tác với khán giả trên các nền tảng phát sóng (Douyin, Bilibili, YouTube).

Methodology

Kiến trúc dạng lai (hybrid edge-cloud): Cloud (Vidu) chỉ đảm nhận render avatar (khẩu hình, biểu cảm, hành động) và đẩy luồng RTC; toàn bộ logic điều khiển nằm tại máy cục bộ (FastAPI bridge cổng :8795).

  1. Giao diện & Cầu nối: Trang quản trị web cục bộ kết nối bridge qua WebRTC để xem trước và điều khiển.
  2. Pipeline thoại & đạn mạc: Bình luận (danmaku) từ bên ngoài gửi tới endpoint /api/danmaku. LLM (DeepSeek / OpenAI compatible) xử lý theo luồng (streaming) -> tách câu -> gửi tới TTS cục bộ.
  3. TTS: Mặc định dùng OmniVoice chạy trên WSL2 + FlashInfer/CUDA Graph (port :9877) tạo luồng PCM, hỗ trợ voice cloning và đổi giọng nóng (voice switching). Nhánh mac hỗ trợ thêm say, edge-tts, SiliconFlow CosyVoice2, MLX.
  4. Quản lý hành vi: Hạt nhân ưu tiên hành động: Hành động của khách VIP (tặng quà >99 kc) > thao tác thủ công > kịch bản sắp đặt sẵn (choreography) > đạn mạc tự động. Tích hợp bộ lọc từ khóa nhạy cảm.

Setup

  • Yêu cầu phần cứng: Windows 10/11 với GPU NVIDIA (≥8GB VRAM, thực tế OmniVoice chiếm ~11GB) chạy WSL2 (Ubuntu 22.04) hoặc Apple Silicon Mac (nhánh mac).
  • Dịch vụ cần có: Tài khoản Vidu (tính phí 1 điểm/giây, yêu cầu số dư ≥45 điểm để khởi tạo), LLM API Key (DeepSeek-flash hoặc tương thích OpenAI).
  • Công cụ phần mềm: Python 3.12, uv, ffmpeg.
  • Sử dụng: Chạy bridge FastAPI bằng python -m src.main hoặc script khởi động, truy cập trang điều khiển tại http://127.0.0.1:8795/stage.

Results

  • Chi phí Vidu: 1 điểm/giây (bắt buộc số dư ≥45 điểm mới mở được phiên live).
  • Dung lượng tải mô hình TTS OmniVoice lần đầu: ~10GB.
  • Yêu cầu âm thanh tham chiếu (clone voice): 3–10 giây, câu đơn, định dạng WAV 16kHz mono, không tạp âm.
  • Mức tiêu thụ VRAM thực tế đo đạc của tác giả: ổn định ở mức ~11GB trên WSL2 (yêu cầu tối thiểu ≥8GB VRAM).

Limitations

Không công bố benchmark định lượng về độ trễ tổng thể (end-to-end latency), RTF hay WER/MOS. Bản phân phối cố tình không chứa avatar model, file âm thanh clone, prompt nhân vật cá nhân hóa, key API và kho bài hát do lý do bản quyền/bảo mật. Phụ thuộc chi phí và hạ tầng render của Vidu Cloud.

Takeaways

Cung cấp một bản thiết kế hệ thống mẫu (blueprint) rất thực dụng cho kỹ sư muốn xây dựng Voice/Avatar Agent phục vụ livestream: kết hợp LLM và TTS on-premise để giảm chi phí API, đồng thời dùng API video cloud theo giây để render chuyển động avatar chất lượng cao.
