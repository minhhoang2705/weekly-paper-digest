README excerpt

Speech synthesis, speech recognition and voice activity detection for voice conversation, in C++ on ggml: Qwen3-TTS, Irodori-TTS, Qwen3-ASR, ReazonSpeech, parakeet and Silero VAD on Metal, Vulkan and the CPU, with an OpenAI-compatible server and live transcription. README: Speech synthesis, speech recognition and voice activity detection for voice conversation, in C++ on ggml Models · Install · Quick start · Documentation · C API English · 日本語 speech.cpp is one command, speech, and one shared library, libspeech, behind one C API, on the CPU, Metal and Vulkan through ggml. The command speaks text, writes the text of recordings, finds where someone speaks in them, transcribes the microphone as someone speaks (speech asr --live), serves OpenAI's audio API and its Realtime transcription over HTTP, and runs a worker process for any program that keeps models loaded between requests, ASIST among them. A time to first audio of a quarter of a second or less. On an Apple M5, Qwen3-TTS 0.6B sends its first audio 0.029 s after the text and Irodori-TTS v4.1-Small-MF 0.16 s after it, and the rest follows while it plays. One executable, nothing else to install. No Python and no CUDA: speech fetches each model by name, one GGUF file with its codec, and runs it on Metal, Vulkan or the CPU. OpenAI's API on your own computer. speech serve answers OpenAI's audio API and its Realtime transcription, so an OpenAI client works by changing its base URL. Checked against the official implementations. Every stage of every model is compared with the model's official implementation, from the same inputs. The page of speech serve --open : pick a model of the catalog, fetch it and try it. Transcribe writes a file or a recording, a region at a time where someone speaks. Live writes the microphone as you speak; the grey text is the utterance still being said. Key idea

speech.cpp là thư viện và công cụ dòng lệnh C++ dựa trên ggml, tích hợp toàn diện TTS, ASR và VAD mà không cần môi trường Python hay CUDA. Dự án hỗ trợ tăng tốc trên Metal, Vulkan và CPU với độ trễ phát âm thanh đầu tiên chỉ từ 0.03-0.04 giây, đồng thời cung cấp HTTP server tương thích OpenAI Audio API.

Problem

Các pipeline hội thoại bằng giọng nói thường cồng kềnh, phụ thuộc vào môi trường Python, PyTorch và CUDA, gây khó khăn cho việc nhúng trên các thiết bị cục bộ (edge/desktop) với độ trễ thấp và quy trình cài đặt đơn giản.

Methodology

Xây dựng toàn bộ hệ thống bằng C++ thuần thông qua một file thực thi speech và thư viện libspeech với C API (speech.h), sử dụng backend ggml hỗ trợ CPU, Metal (Apple Silicon) và Vulkan (Windows/Linux). Các mô hình được đóng gói thành định dạng GGUF duy nhất tích hợp cả codec âm thanh, hỗ trợ quantization (F32, F16, Q8_0). Từng tầng tính toán của mô hình được đối chiếu với tensor từ triển khai gốc để đảm bảo độ chính xác. Dự án tích hợp các mô hình: TTS (qwen3-tts-0.6b/1.7b, irodori-tts, irodori-tts-mf), ASR (qwen3-asr-0.6b/1.7b, reazonspeech-v2, parakeet-tdt), và VAD (silero-vad dung lượng 1.2 MB). Hỗ trợ chạy server OpenAI API (/v1/audio/speech, /v1/audio/transcriptions) và worker process qua giao thức JSON Lines.

Setup

Đo đạc hiệu năng bằng speech-bench vào ngày 2026-10-08 và 2026-10-10 trên Apple M5 (Metal) và NVIDIA RTX 2080 (Vulkan), xử lý từng request đơn lẻ. Dữ liệu đánh giá: TTS đo trên 20 câu tiếng Nhật; ASR đo trên 4,483 câu thuộc tập test Common Voice 8.0 tiếng Nhật và 300 câu FLEURS tiếng Anh. Yêu cầu hệ thống: Linux x64 cần glibc 2.34 trở lên.

Results

  • TTS qwen3-tts-0.6b (Q8_0): Thời gian audio đầu tiên 0.04 s (M5) / 0.03 s (RTX 2080); Real-time factor 0.31 / 0.27; CER đạt 5.8% / 8.0%.
  • TTS qwen3-tts-1.7b (Q8_0): Thời gian audio đầu tiên 0.06 s (M5) / 0.04 s (RTX 2080); Real-time factor 0.42 / 0.32; CER đạt 3.0% / 2.8%.
  • TTS irodori-tts-mf (F16): Thời gian audio đầu tiên 0.25 s (M5) / 0.12 s (RTX 2080); Real-time factor 0.17 / 0.07; CER đạt 6.1% / 7.1%.
  • TTS irodori-tts (F16, 16 steps): Thời gian audio đầu tiên 1.24 s (M5) / 0.52 s (RTX 2080); Real-time factor 0.34 / 0.13; CER đạt 3.2% / 3.2%.
  • ASR parakeet-tdt_ctc-0.6b-ja (F16): CER trên Common Voice ja đạt 7.9% (3.0% khi chấp nhận biến thể chính tả); thời gian trung vị 0.05 s (M5) / 0.04 s (RTX 2080).
  • ASR reazonspeech-v2 (F16): CER trên Common Voice ja đạt 12.0% (7.1%); thời gian trung vị 0.08 s (M5) / 0.11 s (RTX 2080).
  • ASR qwen3-asr-0.6b (Q8_0): CER trên Common Voice ja đạt 11.9% (7.0%); thời gian trung vị 0.13 s (M5) / 0.09 s (RTX 2080).
  • ASR qwen3-asr-1.7b (Q8_0): CER trên Common Voice ja đạt 9.5% (4.7%); thời gian trung vị 0.31 s (M5) / 0.16 s (RTX 2080).
  • ASR parakeet-tdt-0.6b-v3 (F16): WER đạt 8.8% trên FLEURS en; thời gian trung vị 0.09 s (M5) / 0.08 s (RTX 2080).

Limitations

Server HTTP tích hợp (speech serve) lắng nghe trên 127.0.0.1 và không có cơ chế xác thực (authentication). Tài liệu chỉ benchmark xử lý đơn lẻ từng request một, chưa đánh giá tải đa luồng đồng thời; phần lớn benchmark chi tiết tập trung vào tiếng Nhật và tiếng Anh.

Takeaways

Cung cấp một giải pháp C++ gọn nhẹ, hoàn chỉnh cho toàn bộ pipeline đàm thoại giọng nói cục bộ mà không cần cài đặt Python hay CUDA, rất thích hợp để nhúng vào ứng dụng desktop hoặc agent thời gian thực.
